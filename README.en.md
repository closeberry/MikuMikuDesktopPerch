# MikuMikuDesktopPerch

[日本語](README.md)

A desktop mascot that stays resident and shows MMD models (PMX) on your desktop with a transparent background. With original motions generated by the program, the mascot walks around, sits or hangs on the edges of windows, makes little gestures while idle, and reacts to clicks. VMD motions can also be used: as idle motions (several, picked at random), as a motion played now and then, and as click motions.
It runs on Win32 + Direct3D 12 + DirectComposition, and clicks on the parts where no model is drawn go through to the window below.

## About using models and motions

This software includes neither models nor motions (VMD). Prepare the models and motions you use yourself, and **follow the terms of use of each**.

- Some models forbid or restrict use in software other than MMD, resident display such as a desktop mascot, changing their movement (including applying generated motions), or publishing screenshots and videos. Before loading a model, read the terms that come with it (its Readme and the like)
- Do not use them in ways their terms do not allow. When you cannot tell, do not use that model
- The author of this software takes no responsibility for problems caused by using models or motions

## Requirements

- Windows 10/11 (64-bit)
- A GPU that supports DirectX 12
- Microsoft Visual C++ Redistributable (Visual Studio 2015–2022 or later, x64). If it says `MSVCP140.dll` or `VCRUNTIME140.dll` cannot be found when starting, download and install `vc_redist.x64.exe` from [Microsoft's page](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist). It is needed even with Visual Studio installed, if the C++ workload is not

## Building

You need Visual Studio 2022 or later (the "Desktop development with C++" workload, the v143 toolset, and a Windows 10/11 SDK). It builds as C++20.

Before building, put the borrowed code that is not kept in Git in its place ([Borrowed code and licenses](#borrowed-code-and-licenses)). Then open `MikuMikuDesktopPerch.vcxproj` in Visual Studio and build, or run this in the Developer PowerShell for VS:

```powershell
msbuild MikuMikuDesktopPerch.vcxproj /p:Configuration=Release /p:Platform=x64
```

The output goes to `bin\<Configuration>\MikuMikuDesktopPerch.exe`. The shaders (`shaders\*.hlsl`) are compiled with FXC at build time and embedded in the exe.

## Controls

- Left click: the mascot reacts ("When clicked" below)
- Left drag: move
- Mouse wheel (over the mascot): change the size by 10% (up to grow, down to shrink; 50–600%)
- Right click, or right click on the notification area icon: the menu (Talk, Timer, Focus mode, Reminders and to-dos, Open model, Add character, Take this character off, Motion (open, add or close the motion, idle motions, click motions, and walk and run motions), Ride on the active window, Walk left, Walk right, Settings, Exit)
- Double click on the mascot or the notification area icon: Talk (the reaction to a click on the mascot starts after a short wait, until it is clear it is not a double click)
- **Settings**: open with "Settings..." in the menu. Motion (auto behavior, ride on the active window, physics, blink, breathe, look at the mouse) and Display (size, language, outline width, always on top, self-shadow, sun position, start with Windows, check for new versions) take effect as soon as you press OK. Talking (server, model, your name, remember chats, persona) also takes effect at once (deleting and adding memories is saved at once in the memory window). Advanced (drawing fps, motion blur, antialiasing, max texture size, physics rate and iterations, shared toon folder) is read at startup, so when you change it the app asks whether to restart
- Changing the size grows or shrinks the mascot around its feet
- **Language (日本語 / English)**: choose Japanese or English under Display → Language in the settings. With "Auto" (the default), it is Japanese when the Windows display language is Japanese, and English otherwise. Besides the menus, the settings window, the messages, and the fixed lines the characters say, the app asks the LLM to reply in that language (for characters whose persona is left at the default, the persona also becomes the default for that language). It switches as soon as you press OK. The mouth also moves for English replies (vowels are picked roughly from the spelling into mouth shapes, a little slower than Japanese). The voice (VOICEVOX) supports Japanese only
- **Start with Windows**: when checked in the settings, the app starts automatically at sign-in (it registers this exe's path under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` for the current user, and removes it when unchecked). If you move the exe, check it again
- Only one can run at a time. Starting it again while it runs shows a message and exits (to show several characters, add them inside the one app, as in "Multiple characters" below)
- **Multiple characters**: with "Add character..." in the menu, you can put other models on the desktop, up to 4 characters. The menu, double click, drag and wheel act on the character you used them on. The model, the motions (idle motions, the motion played now and then, click motions, walk and run motions), the position, and the voice are remembered for each character. The size is shared: turning the wheel over any character resizes them all together (differences in the models' heights stay) (in the ini, `[Mascot]` is the first character, `[Mascot2]`–`[Mascot4]` the second to fourth). Personas and memories are per model to begin with, so each character talks with its own persona and memories. "Take (name) off" removes that character from the desktop (it cannot be removed when it is the only one). The same model cannot be out twice at once. "Open model..." swaps only that character's model, where it stands (the app does not restart). The settings window edits the voice, persona and memories of the character it was opened on; the other items are shared by all. While the settings window is open, models cannot be swapped or taken off. The characters move around separately; when they go to the active window, the bottom right of the screen, or walk off with auto behavior, they avoid places where another character is (or is heading). When a character stands overlapping another, for example after being dropped there, it walks aside to a free spot (in the middle of an idle motion, it waits for a break first). The notification area icon works as the first character's
  - **About the load**: drawing, physics, expressions and the rest are computed almost once per character. Four characters use about four times the GPU and CPU of one, and on a laptop the fan noise or battery drain may become noticeable. When it is heavy, try fewer characters, lower drawing fps, antialiasing or physics rate under Advanced in the settings, or a smaller size
- **Checking for updates**: while "Check for new versions" is on in the settings (the default), the app checks the latest release on GitHub (closeberry/MikuMikuDesktopPerch) shortly after starting and once a day after that. When there is a new version, one of the characters says so and asks whether to update now (in their own words, if an LLM is set up), and "Yes (update)" and "No" appear at their feet. Choosing "Yes" downloads the release zip, checks it against the SHA-256 GitHub gives, unpacks it with the tar that comes with Windows, checks the exe's version, then replaces the files in this folder and restarts (the settings ini and memories stay). Choosing "No" keeps it from asking until the next start. It does not ask while you are away from the computer or while someone is talking. If the exe is in a folder it cannot write to (Program Files and the like), it cannot update and says so. The app connects to the internet only for this check and the update download (GitHub learns only the app's version; nothing such as your chats is sent)
- **Motion**: a VMD opened with "Open motion..." plays once at once, then now and then every 1.5–4 minutes (when on the ground or on a window; a sitting mascot stands up and warps to the ground at the bottom right of the screen before playing). Its start and end blend smoothly with the poses before and after. While it plays, the mascot does not look at the mouse, walk, or move to windows (moving to a window waits until it ends). Grabbing the mascot stops it. "Close motion" takes off only that motion (if it is playing, it stops smoothly first)
- **Idle motions**: with "Open idle motions...", you can choose VMDs to play while idle. The dialog lets you pick several files at once (choosing again replaces them), and "Add idle motions..." adds to the current list. One motion loops; with several, after one plays to the end, the next is picked at random and blended in over 0.6 seconds (the same one is not picked twice in a row; motions shorter than 4 seconds and one-frame poses are held for 4 seconds). "Close idle motions" takes them all off. The model is not reloaded. Generated motions (walking, sitting and so on) take priority over them. But auto behavior, moving to the active window, sitting or hanging on a window, and the motion played now and then do not start in the middle of an idle motion; they wait for a break (where it played to the end, or the end of the loop). When the mascot comes back from walking or sitting, the idle motion plays from the start, not from the middle (anything you do, such as grabbing or "Walk" in the menu, takes effect at once). Without idle motions, the mascot stands in the app's own idle pose: feet slightly apart and arms down naturally (fingers curled a little), it keeps its weight on one foot (or both) for a while, and now and then shifts it over about 1.5 seconds. The hips move toward and up on the side bearing the weight, and the other leg brings its knee slightly forward and lifts its heel
- **Idle gestures**: in the app's own idle pose, with gaps of about 2 seconds, the mascot does one of these gestures for a few seconds at a time. Just standing is picked like any other gesture. It does not pick either of the last two, and picks the left or right hand at random, so it seldom looks like the same sequence. A hand on the hip / waving (smiling) / a peace sign beside the face (winking) / hands clasped behind / gazing at a palm / hands down and joined in front / a slow stretch (raising the arms with eyes closed, arching back and leaning sideways, then lowering the straight arms out to the sides) / looking around / tilting the head / tucking hair behind an ear / a yawn (covering the mouth) / thinking with a hand on the chin / swaying while humming / small claps (smiling) / looking far away with a hand at the forehead like a salute / pressing both cheeks (smiling). During gestures that move the face, it stops looking at the mouse. It does not gesture while an opened motion plays. Expressions use morphs such as 笑い, にやり, ウィンク, まばたき and あ when the model has them
- **Walk and run motions**: with "Open walk motion..." and "Open run motion...", looping walk and run VMDs that step in place (made to move with 全ての親) can be used instead of the generated walk and run. The speed is measured from the foot IK's movement and the mascot moves at that speed, so a planted foot does not slide. Turning sideways is done by rotating the foot IK, 下半身 and 上半身, and the up and down of センター is moved to グルーブ (全ての親 is not moved). "Close walk and run motions" goes back to the generated ones
- **Dozing**: after 5 minutes without your touching the computer, the mascot closes its eyes where it is and dozes with its head hanging (nodding off now and then). Using the mouse or keyboard wakes it (when standing, it yawns now and then)
- Blinking, breathing and gaze are added on top of the VMD's movement, and also reach the physics (hair and skirt sway). When the mouse stays still for 8 seconds, the head slowly goes back to the motion's own direction

## Talking (a local LLM)

You can chat with an LLM running on this computer. The replies appear in a comic-style speech bubble above the mascot's head. Your chats are not sent outside this computer.

- **Preparing**: set up an LLM server with an OpenAI-compatible API (`/v1/chat/completions`), such as llama.cpp's `llama-server`, [Ollama](https://ollama.com/) or [LM Studio](https://lmstudio.ai/), with a model good at the language you talk in. Google's Gemma 4 E4B is recommended. The setup steps are in [docs/LocalLLM.en.md](docs/LocalLLM.en.md)
- **Setting up**: under Talking in "Settings...", check the server (Ollama's default is `http://127.0.0.1:11434/v1`, LM Studio's `http://127.0.0.1:1234/v1`, and llama-server's is the port you started it on), and pick a model with "Get list". Only servers on this computer (`localhost`, `127.0.0.1`, `::1`) can be used
- **Talking**: "Talk..." in the menu, or a double click on the mascot or the notification area icon, opens an input box at the mascot's feet. Enter sends; Esc or a click elsewhere closes it. The bubble goes away after about as long as it takes to read
- **Lip-sync**: Japanese replies are turned into hiragana readings with the conversion engine of the Windows Japanese IME (MS-IME); English words are read roughly from their spelling. The syllables are laid out at a talking pace of about 7.5 a second (about 5 for English), with short pauses at commas and full stops, and MotionTraceEditor's lip-sync turns them into the movement of the あ, い, う, え, お and ん morphs. The bubble's text also appears up to where it has been said. When the IME's conversion engine is unavailable, kana are kept as they are, and kanji and the like move the mouth with a rough guess at their sound
- **Persona**: with "Persona..." under Talking, you can write a name and a personality and way of speaking for each model (saved in `%LOCALAPPDATA%\MikuMikuDesktopPerch\characters`). The name defaults to the model name written in the PMX, and also shows on the bubble's name tag. The app adds the current date and time and an instruction to "answer in short spoken words that fit in a bubble" when sending
- **Your name**: when set under Talking, the mascot calls you by it. When empty, it is told not to call you by a name
- It remembers the last 6 exchanges, so you can carry on talking (they are forgotten when the app exits, and start over when the model or persona changes)
- **Feelings and gestures**: the LLM is asked to begin each reply with its feeling, one of [smile] [surprise] [troubled] [angry] [sad] [shy] [neutral] (in Japanese, ［笑顔］［驚き］［困り］［怒り］［悲しみ］［照れ］［普通］), which shows in the expression morphs (笑い, にこり, びっくり, 困る, 怒り, 照れ and the like, whichever the model has) (the tag is not shown in the bubble). When standing, the mascot sometimes also makes a fitting gesture (tilting the head, being surprised, pressing its cheeks, thinking, hands on hips). While talking, its head nods slightly with the opening of its mouth
- **Looking at you while talking**: while waiting for a reply, while talking (and a little after), and while the input box is open, the mascot faces the middle of the screen (where you are) instead of the mouse
- **Speaking first**: with "Speak first now and then" on under Talking (on by default), the mascot greets you once in each part of the day — morning, noon, evening, and late at night (not again in the same part, even after a restart) — says "welcome back" when you come back after 15 minutes or more away, and now and then (about once every 45 minutes by default; "Remarks" lets you choose 10 minutes to 2 hours) says a word about something it remembers or the time of day. It does not speak first while you are away from the computer, in the middle of a reply or the input box, or while you use a full-screen app. With several characters, one picked at random among those on the ground or on a window speaks, and while someone is talking (or being talked to), the other characters do not speak first either
- **Characters chatting together**: with two or more characters and "Speak first now and then" on, now and then (about once every 30 minutes by default; "Characters chatting together" lets you choose 10 minutes to 1.5 hours, or "Never"), two characters with nothing else to do chat with each other. One walks over beside the other (warping when they are on different windows), they turn in place to face each other (下半身 and 上半身 rotate, and the feet are set down again facing the same way with the foot IK, so the legs do not twist), look each other in the eyes (with a height difference, each raises or lowers its neck and head from its own eyes to the other's eye level), and take turns saying 4–6 lines in all. Each talks with its own persona, and answers seeing the other's persona and their talk so far (the topic is picked at random from the seasons, food, you, and so on; they may also bring up things they remember about you). Each line appears in the speaker's own bubble, and is also spoken when the voice is on. The next one starts after the one before finishes. Bubbles are shifted sideways so they do not overlap other characters or bubbles already out (even when shifted, the tail comes from above the speaker's head). Grabbing either of them, talking (opening the input box), or making one walk from the menu ends the chat there. It does not start while you are away from the computer. The chats are not put into memories or into the history of your talks. For checking, starting with `--banter` begins a chat 5 seconds after starting
- **Voice (VOICEVOX)**: with "Voice" on under Talking, replies are spoken aloud with [VOICEVOX](https://voicevox.hiroshiba.jp/) (or a voice engine with the same API, such as AivisSpeech) running on this computer. The voice supports Japanese only. There are two ways, chosen in the box below the voice under Talking. "Use the engine" asks VOICEVOX (or that voice engine), started beforehand, over HTTP. "Use its files" needs no running VOICEVOX: given the folder it is installed in (the one with `VOICEVOX.exe`), it loads VOICEVOX CORE (`vv-engine\voicevox_core.dll`, version 0.16), the voice models (`model\*.vvm`) and the dictionary inside it into this app and makes the voice (the DLL is loaded by its full path; only the voice model in use is loaded, when it first speaks; it runs on the CPU; restart after changing the folder). VOICEVOX's files are not included in this app. Either way, pick a voice with "Get list", and hear a sample of it with "Listen". Replies are voiced phrase by phrase at punctuation and played in order, and the lip-sync and the bubble's text follow the voice's timing (parts that could not be voiced move the mouth without a voice). The server is `http://127.0.0.1:50021` by default, and only one on this computer can be used (`VoiceEndpoint` in the ini). Follow the terms of each voice character (credits and so on)
- **Long memory**: when the talk pauses for about 20 seconds (or grows long), the same LLM is asked to write out, one per line, things worth remembering from it (likes, plans, family and pets, things you asked it to remember, and so on), and they are saved for each model. Words like "tomorrow" are turned into dates. In later talks, it recalls the ones that seem related and uses them in its replies (with many memories, ones sharing words with what you said, and newer ones, come first). Greetings and small talk alone leave nothing to remember
- **Checking and deleting memories**: with "Memory..." under Talking, you can see the list of what that model remembers, and delete chosen ones, delete them all, or write and add your own (saved at once). If you exit the app right after talking, the talk not yet looked over is looked over and remembered at the next start (it waits in `<model name>-<number>.pending.txt` until then). To keep it from remembering, uncheck "Remember chats". Memories are saved in `<model name>-<number>.memory.txt` (UTF-8 text, one per line) in `%LOCALAPPDATA%\MikuMikuDesktopPerch\characters`, and are not sent anywhere
- Models that think before answering (Gemma 4, Qwen 3 and the like) are told to answer without thinking (llama.cpp's `chat_template_kwargs.enable_thinking=false`). If `<think>`…`</think>` still gets into the text, that part is not shown. Emoji are removed because the bubble's font cannot show them (♪ ★ ☆ are kept)
- The bubble is a comic-style design with a soft shadow, a gradient outline, a curved tail and the character's name tag; it fades in softly and fades out. While waiting for a reply, three dots bounce in turn
- The LLM only returns text; it is not allowed to touch files, run commands, or the like
- Some character models restrict, in their terms, having an AI speak as that character. Check the model's terms of use and the character's guidelines

## Timers, reminders, to-dos and focus mode

You can ask the characters for timers, reminders at a time, and a to-do list. **This works without an LLM** (common ways of asking are read, and answered with fixed lines). With an LLM set up, the characters answer in their own words, and the LLM reads requests put in other ways.

- **Asking** (in the "Talk" input box):
  - Timers: "remind me in 10 minutes to check the oven", "set a timer for 5 minutes", "5 minute timer"
  - Reminders: "remind me at 3pm to call mom", "remind me tomorrow at 9 to send the report", "remind me every day at 8am to take my medicine", "remind me on friday at 6 pm to buy flowers". A time already gone today, with no day said, is taken as this afternoon's or tomorrow's
  - To-dos: "add milk to my todo list", "what's on my to-do list", "remove milk from my todo list", "I finished the report" (checked off when it names an item on the list). Deadlines can be given too: "add the report to my todo list by friday", "add pay rent to my to-do list due nov 1", "todo: call the bank by tomorrow"
  - Others: "cancel the timer", "how much time is left", "show my reminders", "what do I have today" (today's reminders and to-dos), "start focus mode", "stop focus mode"
  - Japanese works too (「5分後に教えて」「15時に会議って教えて」「やることに牛乳を追加」 and so on)
  - When the words are not one of those ways but mention a time and a request, the LLM (if set up) is asked to read the request. If it is not one, she just talks
- **Menu**: "Timer" sets a 3–60 minute timer at once, and "Stop timers" stops them. "Reminders and to-dos..." opens the list window, where you can add (written like "3pm meeting", "25 min", "every day at 8am medicine"), delete, and check off. A to-do written like "report by friday" gets a deadline
- **When it is time**: a character with nothing else to do tells you with a chime (in her own words, with an LLM), and "Got it" and "Again in 5 min" appear at her feet. If someone is talking, she cuts in after a short wait. A dozing character wakes up to tell you. She stays put until you answer
- **Deadlines**: to-dos with a deadline are listed (in the list and when asked "what's on my to-do list") soonest first, marked like "(due Fri, Oct 30)" or "(overdue)". Ones due tomorrow, today or already are told once a day while you are at the computer (in the morning summary when it is on, otherwise from 7 o'clock; during focus mode work, at the next break)
- **Morning summary**: with "Tell today's reminders and to-dos in the morning" on in the settings (the default), when you start using the computer in the morning (5 to 10 o'clock), a character says good morning and tells you today's reminders (timers aside) and to-dos. Once a day; in her own words with an LLM, otherwise in fixed words. On days with neither, there is just the usual morning greeting (with an LLM)
- **Focus mode (pomodoro)**: starts with "Focus mode" in the menu or "start focus mode" in a talk. Work (25 minutes by default) and breaks (5 minutes by default) take turns, and a character tells you at each turn with a chime. Every fourth break is three times as long. During work, the characters do not start talking to you or to each other. Choosing it in the menu again, or "stop focus mode", ends it; it also ends by itself when you are away for 15 minutes in the middle of a work period. The lengths are under Assistant in the settings
- **Break reminder**: after you use the computer without a break for the time set in "Suggest a break after using the PC for" (60 minutes by default; five minutes away counts as a break), a character suggests a short rest, and again after as long if you keep going. Not during focus mode, which has its own breaks. "Never" turns it off
- **Saving**: timers, reminders and to-dos are saved in `%LOCALAPPDATA%\MikuMikuDesktopPerch\planner.txt` (UTF-8 text) and survive exiting the app (shared by all characters). Ones that came due while the app was not running are told at the next start ("it's past ..."; ones more than a day late are dropped). Nothing is sent anywhere

## Generated motions (experimental)

Movements generated by the program without VMDs. They follow the rules in [docs/MotionRules.en.md](docs/MotionRules.en.md).

- **Ground**: the mascot stands on the ground (the top edge of the taskbar if it is at the bottom, otherwise the bottom of the screen). Since the camera looks slightly from above, the front and lowest point of the soles, not the middle of the feet, is set on the ground line
- **How it is shown**: the window itself is a transparent "stage" covering the whole work area (the screen minus the taskbar), and normally does not move. The mascot's picture (a swap chain) moves within the stage with a DirectComposition offset. With the window moving instead, the window's move and the new frame's display were one refresh apart, and the feet seemed to shake back and forth while walking. The offset is applied in the same composition as the frame, and fractions of a pixel are shifted when drawing. The stage moves only when crossing to another monitor. The stage has an opacity of 254 (covered by a window with opacity 255, Chromium-based apps decide they are hidden and stop drawing)
- **Picture size**: it starts large enough to hold sitting legs, spread hair, and the warp's sparkles. If something still looks like going outside, the 0.25-second check widens it without moving it on screen, and it goes back to the normal size 4 seconds after things settle
- **Always on top**: clicking the taskbar can bring it in front of the mascot. Topmost is set again when the foreground window changes and every 2 seconds (it does not go above the Start menu, notifications and the like)
- **Walking**: the mascot turns sideways and moves with センター while stepping with the foot IK. A foot lands heel first and quickly puts its sole down, stays there until just before the other foot lands, then lifts the heel and pushes off with the toes (rotating about the toes, so they do not sink into the ground), swings forward with the toes down, and raises the toes before landing. The body is lowest a little after landing and highest as the other foot passes (the supporting leg stays almost straight). The arms swing opposite to the legs, a little behind, with the elbows bending slightly as they come forward. The picture and camera move with センター. "Walk left" and "Walk right" in the right-click menu walk about 300 px
- **Running**: the same mechanism as walking, with a shorter cycle, longer strides, and a moment with both feet in the air. The pushing foot kicks its heel up toward the bottom before coming forward; the body leans forward and twists a lot (the neck cancels the twist to keep the head steady), and the arms swing widely with the elbows at right angles
- **Jumping**: a deep crouch → swinging the arms up and taking off → hugging the knees while rising, then stretching the legs toward landing as it starts to fall → the knees give on landing. The path is moved on the window side as a parabola with real gravity (9.8 m/s², taking 1 MMD unit = 8 cm), so it is slowest near the top and faster as it falls. Used to move to a nearby window. In the air, the hair floats up softly
- **Warping**: to a far window, the mascot spins and shrinks, vanishing into a swirl of sparkling particles, and at the destination, the light gathers and it spins back into view. The particles mix small glints, fine glitter, and large flares with long rays, each twinkling. The spin and shrink are display-only transforms that do not affect bones or motions. The physics is smoothly reset while it vanishes
- **Sitting and hanging**: resting poses used on the top edge of windows. Sitting is sideways (the knees pointing left or right), with the upper body and face turned toward you. Hanging is like a chin-up on a bar: elbows bent sideways, gripping the edge beside the face, only the face showing above the edge. The fingers other than the thumb bend as if hooked on the edge (the grip is placed by measuring each model's length from wrist to middle finger). The body is hidden behind that window (topmost is also taken off; the upper arms are turned along their own length so the elbows bend upward). While sitting or hanging, the physics floor (at the height of the edge) is turned off, so physics bones below the waist, such as the skirt, are not pushed against the edge and do not go wild. After standing up, the floor comes back once all rigid bodies are above it again; if any are still below after 1.5 seconds, the physics is smoothly reset first. Not used on the taskbar, where the legs would be hidden off screen. A pose lying on its side is not used, because the physics (hair and skirt) tends to break down
- **When clicked**: a click without dragging gets a reaction. When standing, a click on the head makes it narrow its eyes as if patted and look shy (or press both cheeks), and a click on the body surprises it, followed by one of a laugh / a wave / a peace sign / a head tilt. When sitting or hanging, it just tilts its head and smiles. If walking, it stops to react, and clicks while it reacts are ignored. With VMDs set by "Open click motions..." (several can be chosen), a standing mascot plays one of them at random where it is (not the same one twice in a row) instead of the built-in reactions. Even with idle motions, it reacts on top of them and goes back
- **Being grabbed**: left-dragging the body picks it up, with the legs dangling and swinging behind the movement. Let go, and it falls and lands on the ground, taking the shock in its knees. While being carried and falling, the window's acceleration is given to the physics as inertia, so the hair and skirt float up softly while falling
- **Resetting the physics**: the physics is stopped, the hair and skirt bones are brought back smoothly from their current shape to their original shape over 0.5 seconds, the rigid bodies are put back at those positions, and the physics restarts. This happens automatically when, while standing still, the skirt or hair stays raised well above its usual place (flipped up) for 1 second (at most once every 6 seconds; hanging down is normal, so only upward shifts count). It also happens when warping, and when rigid bodies are left below the floor after sitting or hanging
- **Auto behavior**: when enabled in the settings, the mascot decides every 15–40 seconds whether to walk somewhere nearby
- Sitting and hanging need a グルーブ bone

## Active window mode

Turn it on with "Ride on the active window" in the right-click menu (setting `WindowMode`).

- 0.6 seconds after the foreground window changes, the mascot moves to that window's top edge. If close (within 0.8 times its height sideways, and up to 0.6 times its height upward) it jumps, if on the same level it walks or runs, and otherwise it warps. Targets are visible, not minimized, ordinary windows at least as wide as the mascot (the taskbar, desktop and tool windows are excluded)
- 1–3 seconds after landing, it sits or hangs
- For windows where standing on the top edge would put its head above the screen (such as maximized windows), it goes to the ground at the bottom right of that screen instead
- When the window it is on moves, it moves along. If the window is minimized or closed, it falls
- When sitting, if the cursor comes near the legs overlapping the window (from 下半身 to the feet, including the skirt's width), it walks a little to the side (about 30% of its height) and sits again there. It does not go back. It does not dodge above the top edge or away from the sides of the legs, so you can grab or right-click it there (while hanging, the body is behind the window, so it does not dodge)
- When grabbed and let go, it lands on the top edge of the foreground window if one is right below
- While a full-screen app (a game or presentation) runs, it hides automatically and stops drawing

## For safety

Models and motions are often opened as distributed, so the app is built so that broken or tampered files are unlikely to cause trouble.

- **Checks before loading**: only PMX files that start with `PMX `, are version 2.0 / 2.1, and are 1 GB or less, and VMD files that start with `Vocaloid Motion Data` and are 512 MB or less, are loaded. Files with only their extension changed, or too large, are refused before reaching the parser
- **Broken data**: if PMXLoader causes a memory access violation while loading or preparing pose computation, it is handled as an error instead of crashing (for both PMX and VMD). Models with out-of-range references are rejected before being shown. If the idle motions in the settings cannot be loaded, they are taken off and only the model is shown
- **Textures**: paths pointing to another computer (`\\server\share\...` and the like) are not opened (to keep Windows from connecting to it and handing over credentials). Paths with a colon after the drive letter (alternate data streams and the like) are not opened either. Images are loaded only as the BMP, PNG, JPEG, GIF and TIFF that come with Windows, judged by content, not by extension (image codecs installed later are not used). Sizes up to 16384 pixels each way
- **DLLs**: DLLs loaded by name are not searched for in the working folder
- **Build**: Control Flow Guard, CET compatibility, ASLR and DEP are enabled

## Supported models

- **Humanoid check**: the model has センター, 上半身, 下半身, 首, 頭, and left and right 腕, ひじ, 足, ひざ and 足ＩＫ, and its skeleton is shaped like a human (頭 > 首 > 上半身 > ひざ from high to low, nearly vertical from 上半身 to 頭, with the arms extending to the sides of the body). Models that do not meet this are not loaded, with the reason shown
- **T-stance**: models whose arms are less than 20° from horizontal are shown with the arms lowered to an A-stance close to MMD's standard (35°). Child bones' key rotations are converted to match the correction, so elbows and wrists bend as in the original motion
- **Broken data**: bones with the grant flag but no grant parent are loaded with only that grant disabled. Models with out-of-range references, or ones that make PMXLoader crash while loading, are rejected with a message

## Diagnostic options

```
MikuMikuDesktopPerch.exe --snapshot out.png [frames]
```

Draws the given number of frames (60 by default), then saves the last frame to `out.png` (premultiplied BGRA) and exits.
With `--look <x> <y>`, the cursor position for gaze tracking can be fixed in client coordinates.
`--model <pmx>` chooses another model and `--scale <percent>` the size. `--rest-pose sit|hang` fixes the resting pose on a window; `--walk <px>` makes it walk that far 3 seconds after starting (right is positive); `--click head|body` makes it react to a click on the head / body 1.5 seconds after starting; `--play-motion` plays the motion in the settings right after starting; `--gesture hip|wave|peace|behind|palm|folded|stretch|look|tilt|stand|hair|yawn|think|hum|clap|far|cheeks|pat|surprised|curious|shynod` fixes an idle gesture (the last four are click reactions) (with seconds, such as `stretch@3.5`, a moving gesture is stopped at that moment for the shot); and setting the environment variable `MIKUMIKUDESKTOPPERCH_LOG` to a file name writes out how behavior was decided. `--activity walk|run|jump|sit|lie|hang|grab|fall` shoots with that generated motion fixed, and `--view-yaw <degrees>` turns the camera around to shoot from the side. Diagnostic runs do not rewrite the settings file (ini), and write `out.png.txt` (the arm angle, correction, window size, and errors) next to the output.
`--plan-test <in.txt> <out.txt>` writes how each line of in.txt (UTF-8) is read as a timer, reminder or to-do request (a line starting with `~` is read as typed in the list window).
`--banter` starts the characters chatting together 5 seconds after starting; `--pretend-version <version>` treats this exe as that version, to try the whole update from the check to the install (it checks at once); and `--reading <text> <out.txt>` writes out the reading used for lip-sync.
`--voice-test <VOICEVOX folder> <voice ID> <out.wav>` speaks one sentence using VOICEVOX's files directly (the result in `out.wav.txt`); `--light <side> <height>` sets the sun's position; `--self-shadow 0|1` switches self-shadow; `--doze` shoots the dozing look; and `--walk-motion <vmd>` and `--run-motion <vmd>` set walk and run motions.

```
MikuMikuDesktopPerch.exe --check-list <list.txt> <out.tsv>
```

Loads the models listed in `list.txt` (UTF-8, one PMX path per line) one by one without opening a window, and writes the results of the humanoid and T-stance checks to `out.tsv`.

## Structure

- `src/main.cpp`: each character's window (stage), adding, swapping and removing characters, characters chatting together, asking about updates, the notification area icon and menu, frame timing, click-through and click hit testing, behavior decisions (walking, jumping, warping, resting poses, active window mode), and full-screen app detection
- `src/MascotModel.*`: posing with PMXLoader, physics, morph computation (vertex and UV morphs on the CPU, recomputed only when values change), playing and layering idle motions, the opened motion and click motions, and blinking, breathing and gaze
- `src/GeneratedMotion.*`: generated motions (standing pose, gestures, click reactions, walking, running, jumping, sitting, hanging, being grabbed, falling, landing)
- `src/Surfaces.*`: which windows can be stood on, windows' visible frames, the work area
- `src/Settings.*`: reading and writing the settings file (ini)
- `src/SettingsWindow.*`: the settings window, persona, and memory list
- `src/LocalChat.*`: talking to the local LLM (WinHTTP, streaming, localhost only)
- `src/Voice.*`: making the voice (asking a voice engine, or calling VOICEVOX CORE directly) phrase by phrase in the background
- `src/VoicevoxCore.*`: loads and calls VOICEVOX CORE 0.16's C API from an installed VOICEVOX folder
- `src/Memory.*`: each model's long memory (saving, removing duplicates, picking ones related to the talk)
- `src/ChatWindows.*`: the speech bubbles (GDI+), the input box, and the yes/no choices
- `src/Speech.*`: the reading of replies (Japanese through the IME, English from spelling), the lip-sync timeline, and playing the voice (an output of its own for each character)
- `src/Planner.*`: keeping timers, reminders and to-dos, and reading requests for them (the common ways of asking in Japanese and English, and the form the LLM is asked to answer in)
- `src/PlannerWindow.*`: the list window for reminders and to-dos
- `src/Updater.*`: checking GitHub releases, downloading (SHA-256 check, unpacking, version check), and replacing the files
- `src/Text.*`: switching the language (Japanese / English) and choosing the wording
- `res/`: the icon (`MikuMikuDesktopPerch.ico`) and version information
- `src/MascotRenderer.*`: D3D12 drawing. GPU skinning (BDEF1/2/4, SDEF; QDEF is treated as BDEF4), and toon, sphere, outline and self-shadow close to MMD's standard (a shadow map of depth seen from the light, 2048×2048, following the materials' self-shadow map and self-shadow flags, with shadowed parts in the toon's dark color; as in MMD, materials without a toon get no shadow)
- `src/TextureLoader.*`: loading WIC images (bmp/png/jpg and so on) and TGA, and generating mipmaps on the CPU
