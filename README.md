# MikuMikuDesktopPerch

[English](README.en.md)

デスクトップ上にMMDモデル（PMX）を透過表示する常駐マスコットです。プログラムで生成したオリジナルのモーションで歩いたり、ウィンドウの縁に座ったりぶら下がったり、待機中にしぐさをしたり、クリックに反応したりします。VMDモーションも、待機モーション（複数をランダムに）・ときどき再生するモーション・クリック時のモーションとして使えます。
Win32 + Direct3D 12 + DirectComposition で動作し、モデルが描かれていない部分のクリックは下のウィンドウに抜けます。

## モデル・モーションの利用について

このソフトウェアにはモデルもモーション（VMD）も含まれていません。使うモデルやモーションは各自で用意し、**それぞれの利用規約に従ってください**。

- モデルによっては、MMD以外のソフトでの使用、デスクトップマスコットのような常駐表示、動きの改変（生成モーションを当てることも含みます）、スクリーンショットや動画の公開などを禁止・制限しているものがあります。読み込む前に、モデルに付属の規約（Readmeなど）を確認してください
- 規約で認められていない使い方をしないでください。判断がつかないときは、そのモデルでの使用を控えてください
- モデルやモーションの使用によって生じた問題について、このソフトウェアの作者は責任を負いません

## 動作環境

- Windows 10/11（64bit）
- DirectX 12に対応したGPU
- Microsoft Visual C++ 再頒布可能パッケージ（Visual Studio 2015〜2022以降、x64）。起動時に `MSVCP140.dll` や `VCRUNTIME140.dll` が見つからないと表示される場合は、[Microsoftのページ](https://learn.microsoft.com/ja-jp/cpp/windows/latest-supported-vc-redist)から `vc_redist.x64.exe` をダウンロードしてインストールしてください。Visual Studioが入っていても、C++のワークロードを入れていない環境では必要です

## ビルド

必要なもの：Visual Studio 2022 以降（「C++によるデスクトップ開発」ワークロード、v143ツールセット、Windows 10/11 SDK）。C++20でビルドします。

ビルドの前に、Gitで管理していない借用コードを所定の場所に置いてください（[流用元とライセンス](#流用元とライセンス)）。そのうえで `MikuMikuDesktopPerch.vcxproj` をVisual Studioで開いてビルドするか、Developer PowerShell for VS で次を実行します。

```powershell
msbuild MikuMikuDesktopPerch.vcxproj /p:Configuration=Release /p:Platform=x64
```

出力先は `bin\<Configuration>\MikuMikuDesktopPerch.exe` です。シェーダー（`shaders\*.hlsl`）はビルド時にFXCでコンパイルされ、exeに埋め込まれます。

## 操作

- 左クリック：反応します（下の「クリックしたとき」）
- 左ドラッグ：移動（画面の端より外に下ろすと、走って画面の中に戻ってきます）
- **起動したときの位置**：モニターが複数あるときは、マウスカーソルのあるモニターに出ます（前回いた場所がそのモニターの中なら、その場所に）
- マウスホイール（マスコットの上で）：大きさを10%ずつ変える（上で大きく、下で小さく。50〜600%）
- 右クリック／タスクトレイアイコンの右クリック：メニュー（話しかける、タイマー、集中モード、予定とやること、モデルを開く、キャラクターを追加、このキャラクターを外す、モーション（モーション・待機モーション・クリック時のモーション・ウィンドウの上のモーション・歩く／走るモーションの開く／追加／閉じる）、アクティブウィンドウに乗る、左へ歩く、右へ歩く、ポーズと物理をリセット（トレイからは全員）、設定、終了）
- マスコットかタスクトレイアイコンのダブルクリック：話しかける（マスコットのクリックへの反応は、ダブルクリックでないと分かるまで少し待ってから始まります）
- **設定**：メニューの「設定...」で開きます。動き（おまかせ行動、アクティブウィンドウに乗る、物理演算、まばたき、呼吸、マウスの方を見る）と表示（大きさ、言語、輪郭線の太さ、最前面に表示、セルフシャドウ、太陽の位置、Windowsの起動時に起動、更新を自動で確認）はOKを押すとすぐ反映されます。会話（接続先、モデル、あなたの呼び名、なかよし度、会話の内容を覚える、人物設定）もすぐ反映されます（記憶の削除・追加は、記憶の画面ですぐ保存されます）。詳細（描画のfps、モーションブラー、アンチエイリアス、テクスチャの最大サイズ、物理演算の更新と反復回数、共有トゥーンのフォルダ、描画に使うGPU）は起動時に読み込むので、変えたときは再起動するか尋ねます
- 大きさを変えると、足元を基準に拡大・縮小します
- **言語（日本語／English）**：設定の「表示」の「言語」で、日本語か英語を選べます。「自動」（既定）では、Windowsの表示言語が日本語なら日本語、それ以外なら英語になります。メニュー、設定の画面、メッセージ、キャラクターが決まった文で話すことのほか、LLMにもその言語で返事をするよう頼みます（人物設定を既定のままにしているキャラクターは、人物設定もその言語の既定になります）。OKを押すとすぐ切り替わります。英語の返事でも口パクします（つづりから母音をおおまかに拾って口の形にし、日本語より少しゆっくり動かします）。声（VOICEVOX・AivisSpeech）は日本語だけに対応しています（ほかの言語の声は、外部アプリから音声つきの `/say` で渡せます。「外部アプリからの操作」を参照）
- **Windowsの起動時に起動**：設定でチェックすると、サインイン時に自動で起動します（現在のユーザーの `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` に、このexeのパスを登録します。外すと削除します）。exeを移動したときは、チェックを付け直してください
- 同時に起動できるのは1つだけです。起動中にもう一度起動すると、その旨を表示して終了します（複数のキャラクターを出すときは、下の「複数のキャラクター」のとおり、1つのアプリの中で追加します）
- **複数のキャラクター**：メニューの「キャラクターを追加...」で、ほかのモデルを最大6人までデスクトップに出せます。メニュー・ダブルクリック・ドラッグ・ホイールは、操作したキャラクターに対して働きます。モデル、モーション（待機モーション・ときどき再生するモーション・クリック時のモーション・歩く／走るモーション）、位置、声はキャラクターごとに別々に覚えます。大きさは全員共通で、どのキャラクターの上でホイールを回しても全員がそろって変わります（モデルの身長の違いはそのまま残ります）（iniの `[Mascot]` が1人目、`[Mascot2]`〜`[Mascot6]` が2〜6人目）。人物設定と記憶はもともとモデルごとなので、それぞれのキャラクターが自分の人物設定と記憶で話します。「「名前」を外す」でそのキャラクターをデスクトップから外します（1人だけのときは外せません）。同じモデルを2人同時に出すことはできません。「モデルを開く...」は、そのキャラクターのモデルだけを、いまいる場所で入れ替えます（アプリは再起動しません）。設定の画面は、開いたキャラクターの声・人物設定・記憶を編集し、ほかの項目は全員に共通です。設定の画面を開いている間は、モデルの入れ替えと外すことはできません。キャラクターは別々に動き回り、アクティブウィンドウや画面右下、おまかせ行動で歩いて行くときは、ほかのキャラクターがいる（向かっている）場所を避けます。重なったところに下ろしたときなど、ほかのキャラクターと重なって立っていると、横の空いている所へ歩いてずれます（待機モーションの途中なら、区切りまで待ってから）。タスクトレイのアイコンは1人目のキャラクターのものとして働きます
  - **負荷について**：描画・物理演算・表情などの計算は、ほぼ人数分かかります。4人では1人のときのおよそ4倍、6人では6倍のGPU・CPUを使い、ノートPCではファンの音や電池の減りが気になることがあります（目安として、高速なデスクトップPC・描画30fpsで、1人あたり1フレームに約3msかかります）。重いときは、人数を減らす、設定の「詳細」で描画のfpsやアンチエイリアス、物理演算の更新を下げる、大きさを小さくする、のどれかを試してください
- **更新の確認**：設定の「更新を自動で確認」がオン（既定）のとき、起動の少しあとと、その後1日に1回、GitHub（closeberry/MikuMikuDesktopPerch）の最新のリリースを確認します。となりの「今すぐ確認」を押すと、その場で確認し、最新のときはそう表示します。新しいバージョンがあると、キャラクターのだれか1人が、そのことと、いま更新するかどうかを話し（LLMを設定していれば、その子の言葉で）、足元に「はい（更新する）」「いいえ」が出ます。「はい」を選ぶと、リリースのzipをダウンロードし、GitHubが示すSHA-256と照らし合わせ、Windows付属のtarで展開して、exeのバージョンを確かめてから、このフォルダのファイルを入れ替え、キャラクターがセリフを言い終えてから再起動します（設定のiniや記憶はそのまま残ります）。「いいえ」を選ぶと、次に起動するまでは聞きません。あなたがパソコンを使っていないときや、だれかが話している間は聞きません。exeのあるフォルダに書き込めない場所（Program Filesなど）に置いているときは更新できないので、その旨を表示します。インターネットに接続するのは、この確認と更新のダウンロードのときだけです（GitHubに伝わるのはアプリのバージョンだけで、会話の内容などは送りません。Googleカレンダーを設定したときは、その読み込みにも接続します）
- **モーション**：「モーションを開く」で開いたVMDは、すぐに1回再生し、その後は1.5〜4分おきにときどき再生します（地面やウィンドウの上にいるとき。座っていれば立ち上がり、画面右下の地面へワープしてから再生します）。再生の始めと終わりは前後の姿勢となめらかにつなぎます。再生中はマウスの方を見ず、歩いたりウィンドウへ移ったりもしません（ウィンドウへの移動は再生が終わってから行います）。つまむと再生をやめます。「モーションを閉じる」で、開いたモーションだけを外します（再生中なら、なめらかに止めてから外します）
- **待機モーション**：「待機モーションを開く」で、待機中に再生するVMDを指定できます。ダイアログでは複数のファイルをまとめて選べ（選び直すと入れ替わります）、「待機モーションを追加」で今の一覧に足せます。1つだけならループ再生し、複数あるときは1つを最後まで再生したら、次をランダムに選んで0.6秒かけて切り替えます（同じものは続けて選びません。4秒未満の短いモーションや1フレームだけのポーズは4秒間続けます）。「待機モーションを閉じる」で全部外れます。モデルの再読み込みはしません。生成モーション（歩く・座るなど）の間は、そちらが優先されます。ただし、おまかせ行動・アクティブウィンドウへの移動・ウィンドウの上で座る／ぶら下がる・ときどき再生するモーションは、待機モーションの途中では始めず、1つの区切り（最後まで再生したところ、ループならループの終わり）まで待ちます。歩いたり座ったりして戻ってきたときは、待機モーションを途中からではなく最初から再生します（つまむ・メニューの「歩く」など、操作したときはすぐ動きます）。指定していないときは、アプリ標準の待機ポーズで立ちます：足を少し開いて腕を自然に下ろし（指は軽く曲げます）、重心を片足（または両足）にかけたまましばらく保ち、ときどき1.5秒ほどかけて乗せ替えます。体重の乗った側へ腰が寄って上がり、反対の脚はひざを少し前に出してかかとを浮かせます
- **しぐさを選ぶ**：設定の「動き」にある「しぐさを選ぶ...」で、待機中のしぐさと組み込みの待機モーションのうち、使うものだけにチェックを付けられます（既定はすべて使います。あとから加わったものも使います）。すべて外すと、しぐさをせずに立っています
- **待機中のしぐさ**：アプリ標準の待機ポーズでは、2秒ほどの間を空けながら、次のしぐさのどれかを数秒間ずつします。ただ立っているのも、しぐさの一つとして同じように選ばれます。直前の2つと同じものは選ばず、左右の手もランダムに変えるので、続けて見ても同じ流れになりにくくしています。腰に片手を当てる／手を振る（笑顔）／顔の横でピース（ウインク）／手を後ろで組む／手のひらをじっと見る／手を下げて前で重ねる／ゆっくり伸びをする（腕を上げて目を閉じ、体を反らして横に傾け、ひじを伸ばしたまま腕を横から下ろす）／きょろきょろ見回す／首をかしげる／髪を耳にかける／あくび（手で口を隠す）／あごに手を当てて考える／鼻歌まじりに体を揺らす／小さく拍手する（笑顔）／敬礼のように額の横へ手をかざして遠くを見る／両手でほっぺを押さえる（笑顔）。これに加えて、何気ない動きもします：腕をぶらぶらさせる／片腕をなんとなく振る／手をぶらぶら振る／手首を回す／指を動かす／肩を回す／肩をすくめる／ため息をつく／振り返って後ろを見る／足もとを見る／上を見る／物音にちらっと目をやる／首を伸ばす／ひとりでうなずく／一瞬うとうとする／体を左右に揺らす／腰をひねる／前かがみにのぞき込む／ひざでリズムをとる／つま先でトントンする。腕は立ちポーズと同じように肩から下げたまま前後に振ったり外へ開いたりするだけで、内側へは寄せないので、手が腰やスカートにめり込みません。顔を動かすしぐさの間は、マウスの方を見るのを止めます。開いたモーションの再生中はしぐさをしません。表情はモデルに「笑い」「にやり」「ウィンク」「まばたき」「あ」などのモーフがあれば使います
- **歩く・走るモーション**：「歩くモーションを開く」「走るモーションを開く」で、その場で足踏みするループの歩き・走りのVMD（全ての親で移動させる作りのもの）を、生成の歩き・走りの代わりに使えます。足ＩＫの動きから進む速さを測り、その速さで進むので、着いている足は滑りません。横向きにするのは足ＩＫ・下半身・上半身の回転で行い、センターの上下はグルーブに移します（全ての親は動かしません）。「歩く・走るモーションを閉じる」で生成のものに戻ります
- **うとうと**：パソコンを5分間さわらないでいると、その場で目を閉じて、首を垂れてうとうとします（ときどきこっくりします）。マウスかキーボードを使うと起きます（立っているときは、ときどきあくびをします）
- まばたき・呼吸・視線はVMDの動きに上乗せされ、物理演算（髪やスカートの揺れ）にも反映されます。マウスが8秒間止まっていると、首の向きはモーション本来の向きにゆっくり戻ります

## 話しかける（ローカルLLM）

このコンピューターで動くLLMとおしゃべりできます。返事はマスコットの頭の上に、漫画のような吹き出しで表示されます。会話の内容は、このコンピューターの外には送りません。

- **準備**：llama.cpp の `llama-server`、[Ollama](https://ollama.com/)、[LM Studio](https://lmstudio.ai/) など、OpenAI互換のAPI（`/v1/chat/completions`）を持つLLMのサーバーを用意し、日本語が得意なモデルを入れておきます。おすすめは Google の Gemma 4 E4B です。導入手順は [docs/LocalLLM.md](docs/LocalLLM.md) にまとめました
- **設定**：「設定...」の「会話」で接続先（Ollamaの既定は `http://127.0.0.1:11434/v1`、LM Studioは `http://127.0.0.1:1234/v1`、llama-server は起動したポート）を確かめ、「一覧を取得」でモデルを選びます。接続先には、このコンピューター（`localhost`、`127.0.0.1`、`::1`）のサーバーしか指定できません
- **話しかける**：メニューの「話しかける...」か、マスコットやタスクトレイアイコンのダブルクリックで、マスコットの足元に入力欄が出ます。Enterで送り、Escかほかの場所をクリックすると閉じます。読み終わるくらいの時間がたつと吹き出しは消えます
- **口パク**：返事の文章をWindowsの日本語IME（MS-IME）の変換エンジンでひらがなの読みにし、1秒に7.5音ほどの話す速さで並べ（読点・句点では少し間を空けます）、MotionTraceEditor の口パク生成で「あ」「い」「う」「え」「お」「ん」モーフの動きにします。吹き出しの文字も、しゃべった所まで表示されていきます。IMEの変換エンジンが使えないときは、かなはそのまま、漢字などはおおよその音で口を動かします
- **人物設定**：「会話」の「人物設定...」で、モデルごとに名前と性格・話し方を書けます（`%LOCALAPPDATA%\MikuMikuDesktopPerch\characters` に保存）。名前の既定値はPMXに書かれているモデル名で、吹き出しの名前札にも出ます。アプリは、いまの日時と「吹き出しに収まる短い話し言葉で答える」指示を足して送ります。人物設定は4,000文字まで書けます（画面の下に文字数が出て、超えるとOKを押したときに知らせます）。ただし、実際にどこまで効くかはLLMのサーバーの設定によります。人物設定は、話しかけるたびに、指示・覚えていること（最大1,500文字）・直近の会話と一緒に送るので、これらの合計がサーバーの扱える長さ（コンテキスト長：Ollama では `num_ctx`、LM Studio ではモデルを読み込むときの Context Length、llama.cpp では `-c`）に収まる必要があります。超えると、多くのサーバーは先頭から読まなくなるため、人物設定から先に効かなくなります。日本語はおおよそ1文字が1トークン前後なので、コンテキスト長が4,096トークン程度なら、人物設定は数百〜1,000文字くらいに要点をまとめるのがおすすめです（小さなモデルは、長い人物設定を細かく守れないこともあります）。キャラクター同士のおしゃべりでは、相手の人物設定は先頭の400文字だけを渡します
- **あなたの呼び名**：「会話」で設定すると、マスコットはその名前で話しかけてきます。空のときは、名前で呼ばない（「◯◯さん」とも書かない）よう指示します
- 直近の6往復ぶんの会話を覚えていて、続けて話せます（アプリを終了すると忘れます。モデルや人物設定を変えたときも最初からです）
- **気持ちと仕草**：返事の最初に、そのときの気持ちを［笑顔］［驚き］［困り］［怒り］［悲しみ］［照れ］［普通］のどれかで書くようLLMに頼み、表情モーフ（笑い、にこり、びっくり、困る、怒り、照れ など、モデルにあるもの）に反映します（印は吹き出しには出しません）。立っているときは、ときどき合う仕草（首をかしげる、驚く、ほっぺを押さえる、考える、手を腰に）もします。話している間は、口の開きに合わせて頭が小さくうなずきます
- **話すときはこちらを見る**：返事を待つ間、話している間（と、そのあと少し）、入力欄を開いている間は、マウスではなく画面のまん中（あなたがいるあたり）の方を向きます
- **自分から話しかける**：「会話」の「ときどき自分から話しかける」をオンにすると（既定でオン）、朝・お昼・夕方〜夜・夜遅くの時間帯ごとに1回あいさつし（再起動しても同じ時間帯には繰り返しません）、15分以上席を外して戻ってくると「おかえり」と言い、ときどき（既定では45分に1回くらい。「ひと言」の間隔は10分〜2時間から選べます）、覚えていることや時間帯にちなんだひと言を話しかけます。あなたがパソコンを使っていないとき、返事や入力欄の途中、全画面のアプリを使っているときは話しかけません。キャラクターが複数いるときは、そのとき地面やウィンドウの上にいるキャラクターの中からランダムに1人が話しかけ、だれかが話している間（話しかけられている間）はほかのキャラクターも話しかけません
- **キャラクター同士のおしゃべり**：キャラクターが2人以上いて「ときどき自分から話しかける」がオンのとき、ときどき（既定では30分に1回くらい。「キャラクター同士のおしゃべり」で10分〜1時間半の間隔か「しない」を選べます）、手の空いている2人がおしゃべりします。1人がもう1人のとなりへ歩いて行き（別のウィンドウの上にいるときはワープして）、その場で相手の方へ向き直り（下半身と上半身を回し、足ＩＫで足も向きをそろえて置き直すので、脚はねじれません）、相手の目を見て（身長差があれば、自分の目から相手の目の高さへ首と頭を上げ下げします）、交互に1つずつ、全部で4〜6個のセリフを言い合います。それぞれが自分の人物設定で話し、相手の人物設定と、それまでの二人の会話を見て返します（話題のきっかけは、季節や食べ物、あなたのことなどからランダムに選びます。あなたについて覚えていることを話に出すこともあります）。セリフは自分の吹き出しに出て、声で話す設定なら声でも話します。前の人が言い終わってから、次の人が話し始めます。吹き出しは、ほかのキャラクターや、先に出ている吹き出しに重ならないよう横にずらして出します（ずらしても、しっぽは自分の頭の上から出ます）。どちらかをつまむ、話しかける（入力欄を開く）、メニューで歩かせると、おしゃべりはそこで終わります。あなたがパソコンを使っていないときは始めません。おしゃべりの内容は、記憶にも、あなたとの会話の履歴にも入れません。確認用に、`--banter` を付けて起動すると、起動の5秒後におしゃべりを始めます
- **声で話す（VOICEVOX・AivisSpeech）**：「会話」の「声で話す」をオンにすると、このコンピューターで動く [VOICEVOX](https://voicevox.hiroshiba.jp/) か [AivisSpeech](https://aivis-project.com/) で返事を声に出します。どれを使うかは、「会話」の声の下の欄で選びます。「VOICEVOX」と「AivisSpeech」では、そのアプリを起動しておき、HTTPで頼みます（接続先はそれぞれ `http://127.0.0.1:50021` と `http://127.0.0.1:10101`）。AivisSpeech の声は話す速さを声ごとに決めるので、口パクは声の音から、声が出ているところに音節を割り振って合わせます。AivisSpeech では、その下の「スタイルの強さ」で、声のスタイル（あまあま、ねむたい など）をどれだけはっきり出すかを選べます（0.5〜2.0、標準は1.0。強いほどスタイルごとの違いがはっきりします）。「VOICEVOXのファイル」では、VOICEVOXを起動しなくても、インストールしたフォルダ（`VOICEVOX.exe` のあるフォルダ）を指定すると、その中の VOICEVOX CORE（`vv-engine\voicevox_core.dll`、対応は0.16）・声のモデル（`model\*.vvm`）・辞書を、このアプリの中に読み込んで声を作ります（DLLはフルパスで読み込みます。使う声のモデルだけを、最初に話すときに読み込みます。CPUで動かします。フォルダを変えたときは再起動してください）。VOICEVOXのファイルはこのアプリには含まれていません。どれでも「一覧を取得」で声を選び（使うものを変えたら、取り直してください）、「試聴」でその声のサンプルを聞けます。返事は句読点ごとに声にして順に再生し、口パクと吹き出しの文字はその声のタイミングに合わせます（声にできなかった部分は、声なしで口パクだけします）。接続先はこのコンピューターのものだけを使えます。同じAPIのほかの音声エンジンは、「VOICEVOX」を選んで、iniの `VoiceEndpoint` にその接続先を書くと使えます。声のキャラクターごとの利用規約（クレジット表記など）に従ってください
- **長い記憶**：会話が20秒ほど途切れると（または長くなると）、話した内容から覚えておくとよいこと（好きなもの、予定、家族やペット、「覚えておいて」と言ったことなど）を、同じLLMに1行ずつ書き出させて、モデルごとに保存します。「明日」などは日付に直して覚えます。次からの会話では、話に関係のありそうなものを思い出して返事に生かします（記憶が多いときは、話した言葉と重なるものと新しいものを優先します）。あいさつや雑談だけのときは何も覚えません
- **記憶の確認・削除**：「会話」の「記憶...」で、そのモデルが覚えていることの一覧を見て、選んで削除したり、すべて削除したり、自分で書いて追加したりできます（すぐ保存されます）。会話の直後にアプリを終了しても、まだ見ていない会話は次に起動したときに見直して覚えます（それまで `<モデル名>-<番号>.pending.txt` に置きます）。覚えさせたくないときは「会話の内容を覚える」を外します。記憶は `%LOCALAPPDATA%\MikuMikuDesktopPerch\characters` の `<モデル名>-<番号>.memory.txt`（UTF-8のテキスト、1行に1件）に保存し、外部には送りません
- **なかよし度**：キャラクターごとに、あなたとの仲の良さを数値で持ちます。パソコンを使っている間そのキャラクターがデスクトップにいる（1日に合計10分で、その日を「一緒に過ごした日」として数えます）、話しかける、クリックする、集中モードの作業を終える、やることを済ませる、で上がります（1日に30まで。下がることはありません）。仲は「はじめまして」「顔なじみ」「なかよし」「大のなかよし」「相棒」と深まり、1か月ほどで「相棒」になります。LLMにはその仲を伝え、人物設定の話し方を守ったまま、少しずつ打ち解けた話し方になります（人物設定より素っ気なくなることはありません）。なかよし度ができる前から一緒にいたキャラクターは、いちばん古い記憶の日付（記憶がなければ、設定のiniが作られた日付）から一緒にいたものとして、途中の段階（最低でも「なかよし」）から始まります。数値は「相棒」になってからも上がり続け、仲が深まったとき、一緒に過ごした日が7日・30日・100日（以降100日ごと）になったとき、出会ってから1年ごと、なかよし度が1,000・3,000・5,000・10,000（以降10,000ごと）を超えたときに、そのキャラクターが話題にします（1日に1つまで）。「なかよし度は？」と聞くと答えます。`%LOCALAPPDATA%\MikuMikuDesktopPerch\characters` の `<モデル名>-<番号>.bond.dat` に保存し、外部には送りません。設定の「会話」の「なかよし度」を外すと止まります（iniの `Bond`）。詳しくは [docs/Bond.md](docs/Bond.md)
- **アルバム**：キャラクターと吹き出しを写真に残します。なかよし度の節目や記念日を話したときは、言い終えたところで自動で撮ります。メニューの「この瞬間を撮る」か、どこでも効くショートカット（既定は Ctrl+Alt+Shift+S。設定の「秘書」の「アルバム」で変えられ、なしにもできます）で、デスクトップにいる全員とそのときの吹き出しを撮れます（シャッター音は同じ所でオフにできます）。**画面を撮るのではなく、アプリが自分で描いたキャラクターと吹き出しの絵を使うので、後ろのウィンドウやデスクトップは写りません**。背景は淡いグラデーションです。1回ごとに吹き出しありと吹き出しなしの2枚を保存します（共有するときは吹き出しなしをどうぞ。セリフに名前や予定が入っていることがあります）。`%LOCALAPPDATA%\MikuMikuDesktopPerch\album` の `auto`（自動）と `manual`（手動）に保存し、セリフは `album.txt` にも残します。保存先は設定の「秘書」の「アルバム」で変えられます（変えたときは、それまでの写真を新しい保存先にコピーします。同じ名前のファイルは上書きせず、元のフォルダは消さずに残します）。外部には送りません。メニューの「アルバムを開く」でフォルダを開きます。詳しくは [docs/Album.md](docs/Album.md)
- 考えてから答えるモデル（Gemma 4、Qwen 3 など）には、考えずに答えるよう指定して送ります（llama.cpp の `chat_template_kwargs.enable_thinking=false`）。それでも `<think>`〜`</think>` が本文に混じったら、その部分は表示しません。絵文字は吹き出しのフォントで表示できないため取り除きます（♪ ★ ☆ は残します）
- 吹き出しは、柔らかい影、グラデーションの縁取り、曲がったしっぽ、キャラクターの名前札の付いた漫画風のデザインで、ふわっと現れてフェードアウトします。返事を待つ間は3つの点が順に跳ねます
- LLMは文章を返すだけで、ファイルの操作やコマンドの実行などはさせていません
- キャラクターのモデルでは、AIにそのキャラクターとして話させることを規約で制限していることがあります。モデルの利用規約やキャラクターのガイドラインを確認してください

## タイマー・リマインダー・やること・集中モード

キャラクターに、タイマー、時刻に知らせるリマインダー、やることリストを頼めます。**LLMなしでも使えます**（決まった言い方を読み取り、決まった文で答えます）。LLMを設定していれば、キャラクターが自分の言葉で答え、決まった言い方でない頼み方もLLMに読み取ってもらいます。

- **話しかけて頼む**（「話しかける」の入力欄で）：
  - タイマー：「5分後に教えて」「25分タイマー」「3分計って」「10分後に洗濯物を取り込むって教えて」「1時間半後にお風呂を沸かすって知らせて」
  - リマインダー：「15時に会議って教えて」「明日の朝7時に起こして」「毎日8時に薬を飲むって教えて」「来週の月曜の9時にゴミ出しって教えて」「10月30日の14時に歯医者って教えて」。日付を言わずに、もう過ぎた時刻を言ったときは、午後のその時刻か、明日のその時刻になります（13時に「3時に」なら15時）
  - やること：「やることに牛乳を買うを追加」「宿題もToDoに入れておいて」「やることは？」「ToDoから牛乳を消して」「宿題終わった」（やることにある名前が入っていれば、済みにします）。期限も付けられます：「やることに金曜までにレポートを追加」「申込書をToDoに入れて、締め切りは来週の月曜」「ToDo: 今日中に電話する」
  - そのほか：「タイマー止めて」「タイマーあと何分？」「明日の予定は？」（セットしているタイマーとリマインダーを話します）、「今日の予定は？」（今日のリマインダーとやることを話します）、「集中モード始めて」「集中モード終わり」
  - 英語でも頼めます（"remind me in 10 minutes to check the oven"、"remind me at 3pm to call mom"、"add milk to my todo list" など）
  - 決まった言い方で読み取れず、時間やお願いの言葉が入っているときは、LLMを設定していれば、LLMに頼みの中身を読み取ってもらいます（例：「お茶が入るまで3分待ってて、できたら呼んで」）。頼みでなければ、ふつうに会話します
- **メニュー**：「タイマー」から3〜60分のタイマーをすぐにセットでき、「タイマーを止める」で止められます。「予定とやること...」で一覧の画面を開き、追加（「15時に会議」「25分」「毎日8時に薬」のように書きます）、削除、済みにすることができます。やることは「金曜までにレポート」のように書くと期限が付きます
- **知らせるとき**：時間になると、手の空いているキャラクターが、通知音を鳴らして知らせ（LLMを設定していれば、その子の言葉で）、足元に「わかった」「5分後にもう一度」が出ます。だれかが話していても、少し待ってから割り込みます。うとうとしていても起きて知らせます。答えるまで、そのキャラクターはその場で待ちます
- **やることの期限**：期限のあるやることは、一覧や「やることは？」で期限の近い順に「（金曜まで）」「（期限切れ）」のように付けて話します。期限が明日・今日・過ぎたものは、1日に1回、パソコンを使っているときに知らせます（朝のまとめがオンなら朝のまとめで、そうでなければ7時以降に。集中モードの作業中は休憩まで待ちます）
- **朝のまとめ**：設定の「朝に、今日のリマインダーとやることを話す」がオン（既定）のとき、朝（5〜10時）にパソコンを使い始めると、キャラクターがあいさつと一緒に、今日のリマインダー（タイマーは除く）とやることを話します。1日に1回です。LLMを設定していればその子の言葉で、なければ決まった文で話します。今日のリマインダーもやることもない日は、ふだんの朝のあいさつ（LLMがあるとき）だけです
- **集中モード（ポモドーロ）**：メニューの「集中モード」か、「集中モード始めて」と話しかけると始まります。作業（既定25分）と休憩（既定5分）をくり返し、区切りごとにキャラクターが通知音とともに知らせます。4回目の休憩は3倍の長さです。作業の間は、キャラクターから話しかけたり、キャラクター同士でおしゃべりしたりしません。もう一度メニューを選ぶか、「集中モード終わり」で終わります。作業の途中で15分以上パソコンを使っていないと、自動で終わります。長さは設定の「秘書」で選べます
- **休憩のすすめ**：設定の「使い続けたら休憩をすすめる」（既定60分）の間、休まずにパソコンを使い続けると（5分以上使わなければ休んだとみなします）、キャラクターが少し休憩するようすすめます。その後も休まなければ、同じ間隔でもう一度すすめます。集中モードの間は、集中モードの休憩があるのですすめません。「しない」で止められます
- **Googleカレンダー**：設定の「秘書」の「Googleカレンダー」に、カレンダーの「iCal形式の非公開アドレス」を入れると、予定を読み込んで、朝のまとめ・「今日の予定は？」「明日の予定は？」で話し、予定の少し前（既定10分前。「カレンダーの予定の前に知らせる」で変えられます）に知らせます（終日の予定は知らせません）
  - アドレスの調べ方：パソコンのブラウザでGoogleカレンダーを開き、設定 →（左の一覧で）使うカレンダー →「カレンダーの統合」→「iCal形式の非公開アドレス」をコピーします
  - **このアドレスはパスワードと同じです**。知られると予定を読まれてしまうので、人に見せたり、どこかに貼ったりしないでください。漏れたかもしれないときは、同じ画面の「リセット」で作り直せます（古いアドレスは使えなくなります。その後、新しいアドレスを入れ直してください）
  - 読むだけで、カレンダーに書き込んだり予定を消したりはしません。アドレスは、このWindowsユーザーにしか読めないよう暗号化（DPAPI）して設定ファイルに保存し、設定の画面でも伏せ字で表示します。ログにも書きません。接続先は calendar.google.com だけ（HTTPS、ほかの場所への転送はたどりません）で、30分ごとに今日から3日分の予定を読み込みます。予定の内容は、このコンピューターのLLMにだけ渡します
  - 繰り返しの予定（毎日・毎週・毎月・毎年）、繰り返しの一部の変更・削除にも対応しています。タイムゾーン付きの時刻は、このパソコンの時刻として扱います（カレンダーとパソコンのタイムゾーンが違うと、時刻がずれます）
  - 使うのをやめるときは、アドレスを消してOKを押します
- **保存**：タイマー・リマインダー・やることは `%LOCALAPPDATA%\MikuMikuDesktopPerch\planner.txt`（UTF-8のテキスト）に保存し、アプリを終了しても残ります（キャラクター全員で共通です）。アプリを起動していない間に時間が来たものは、次に起動したときに「過ぎちゃってたよ」と知らせます（1日以上過ぎたものは知らせません）。外部には送りません

## 生成モーション（試作）

VMDを使わず、プログラムで生成する動きです。作法は [docs/MotionRules.md](docs/MotionRules.md) に従います。

- **地面**：マスコットは地面（タスクバーが下にあればその上端、なければ画面の下端）に立ちます。カメラが少し上から見ているので、足の中心ではなく靴底の前端・最下点を地面の線に合わせています
- **表示のしくみ**：ウィンドウ自体は作業領域（タスクバーを除く画面）全体を覆う透明な「舞台」で、普段は動かしません。マスコットの絵（スワップチェーン）をDirectCompositionのオフセットで舞台の中で動かします。ウィンドウを動かす方式では、ウィンドウの移動と新しいフレームの表示が1リフレッシュずれ、歩くと足が前後に震えて見えたためです。オフセットはフレームと同じ合成で反映され、端数のピクセルは描画側でずらします。舞台はモニターをまたいだときだけ移動します。舞台は不透明度254にしてあります（不透明度255のウィンドウに覆われると、Chrome系のアプリは隠れたと判断して描画を止めるため）
- **絵の大きさ**：座ったときの脚、広がった髪、ワープの光の粒まで収まる大きさで始めます。それでもはみ出しそうなときは、0.25秒ごとの確認で画面上の位置を変えずに広げ、落ち着いてから4秒たつと元の大きさに戻します
- **最前面**：タスクバーをクリックすると、タスクバーがマスコットより前に出ることがあります。前面のウィンドウが切り替わったときと2秒ごとに、最前面を設定し直します（スタートメニューや通知などの上には出ません）
- **歩く**：横向きになり、足ＩＫで足を運びながらセンターで進みます。足はかかとから着地してすぐ足裏をつき、反対の足が着地する直前までそのまま、それからかかとを上げてつま先で蹴り出し（つま先を支点に回すので、つま先は地面に沈みません）、つま先を下げたまま前へ振り出して、着地の前につま先を上げます。体は着地の少しあとに一番沈み、反対の足が通り過ぎるころに一番高くなります（支えている脚はほぼまっすぐのままです）。腕は脚と逆に少し遅れて振り、前へ出るときにひじが少し曲がります。絵とカメラはセンターに合わせて移動します。右クリックメニューの「左へ歩く」「右へ歩く」で約300px歩きます
- **走る**：歩きと同じ仕組みで、周期を短く・歩幅を広くし、両足が浮く瞬間を入れています。蹴り出した足はかかとをお尻の方へ跳ね上げてから前へ運び、体は前に傾けて大きくひねり（首はひねりを打ち消して頭を安定させます）、ひじを直角に曲げて腕を大きく振ります
- **ジャンプ**：深くかがむ → 腕を振り上げて踏み切る → 上昇中はひざを抱え、落ち始めると着地に向けて脚を伸ばす → 着地でひざが沈む。軌道はウィンドウ側で動かし、実際の重力加速度（9.8m/s²、MMDの1単位=8cmとして換算）の放物線なので、頂点に近づくほど遅く、落ちるほど速くなります。近くのウィンドウへ乗り移るときに使います。滞空中は髪がふわっと浮きます
- **ワープ**：遠くのウィンドウへは、回転しながら小さくなってきらきらした光の粒の渦に消え、行き先で逆に光が集まって回転しながら現れます。光の粒は、小さなきらめき・細かいラメ・光条の長い大きな輝きを混ぜ、それぞれが明滅します。回転と縮小は表示だけの変換で、ボーンやモーションには影響しません。消えていく間に物理演算をなめらかにリセットします
- **座る・ぶら下がる**：ウィンドウの上端で使う休憩ポーズです。座るときは横向き（ひざが左右どちらかを向く）で、上半身と顔は正面へ振り向きます。ぶら下がるは鉄棒の懸垂のように、ひじを横に曲げて顔の横で縁をつかみ、顔だけを縁から出します。親指以外の指は縁に掛けるように曲げます（つかむ位置は、手首から中指までの長さをモデルごとに測って合わせます）。体はそのウィンドウの後ろに隠れます（最前面も外します。上腕はひじが上へ曲がる向きに、腕ボーン自身を長さ方向に回して合わせています）。座っている間とぶら下がっている間は物理演算の床（縁の高さ）を切るので、スカートなど腰より下の物理ボーンが縁に押し付けられて暴れません。立ち上がったあとは、物理の剛体がすべて床より上に戻ってから床を戻し、1.5秒たっても下に残っていれば物理をなめらかにリセットしてから戻します。タスクバーの上では脚が画面外に隠れるので使いません。横向きに寝そべるポーズは、物理演算（髪やスカート）が破綻しやすいため使いません
- **クリックしたとき**：ドラッグせずにクリックすると反応します。立っているときは、頭をクリックするとなでられたように目を細めて照れる（または両手でほっぺを押さえる）、体をクリックするとびっくりしてから笑う／手を振る／ピース／首をかしげる、のどれかをします。座っている・ぶら下がっているときは、首をかしげて微笑むだけです。歩いている途中なら立ち止まって反応し、反応している間のクリックは無視します。「クリック時のモーションを開く」でVMDを指定すると（複数選択可）、立っているときは組み込みの反応の代わりに、その中から1つをランダムに（同じものは続けずに）その場で再生します。待機モーションを使っていても、その上から反応して元に戻ります
- **つままれる**：体を左ドラッグすると持ち上がり、脚がぶら下がって動きに遅れて揺れます。離すと落下して地面に着地し、ひざで衝撃を吸収します。持ち上げ中と落下中は、ウィンドウの加速度を物理演算に慣性として与えるので、落下中は髪やスカートがふわっと浮きます
- **物理演算のリセット**：物理演算を止め、髪やスカートのボーンを今の形から元の形へ0.5秒かけてなめらかに戻し、剛体をその位置に置き直してから物理演算を再開します。立ち止まっている間、スカートや髪が普段の位置より大きく上に上がったまま（捲れたまま）1秒続いたときに自動で行います（6秒に1回まで。垂れ下がるのは普通なので、上向きのずれだけを見ます）。ワープのときと、座る・ぶら下がるから戻って床の下に剛体が残ったときにも行います
- **おまかせ行動**：設定で有効にすると、15〜40秒ごとに、近くへ歩くかどうかを自分で決めます
- **組み込みの待機モーション**：exeに埋め込んだVMDを、待機中のしぐさの一つとして、ほかのしぐさと同じようにランダムに選んで再生します（立ちポーズから0.7秒かけて入り、終わると0.7秒かけて戻ります）。待機モーションを設定しているときは使いません。歩き出したり持ち上げられたりすると、すぐに戻ります。いまは「あくび」「うーん、あっ！」「すみません」「よりかかる」「どけざ」「ダブルピース」「バレエくるくる」「レッツゴ」「体操」「周りを見渡す」「宙に浮く」「屈伸」「片足くるりん」「きいてきいて」の14個です（設定の「しぐさを選ぶ...」では「モーション：あくび（絢姫 様）」のように、作者の名前を添えて並びます。作者は下の「組み込みの待機モーションの作者」に記載しています）
- 座る・ぶら下がるにはグルーブボーンが必要です

## アクティブウィンドウモード

右クリックメニューの「アクティブウィンドウに乗る」で有効にします（設定 `WindowMode`）。

- 前面のウィンドウが切り替わって0.6秒たつと、そのウィンドウの上端へ移ります。すぐ近く（横に身長の0.8倍以内で、上りは身長の0.6倍まで）ならジャンプ、同じ面の上なら歩くか走る、それ以外はワープです。対象は、見えていて最小化されていない普通のウィンドウで、マスコットの幅以上あるものです（タスクバー・デスクトップ・ツールウィンドウは対象外）
- 着地して1〜3秒たつと、座るかぶら下がるになります
- **ウィンドウの上のモーション**：「座る」「ぶら下がる」のほかに、VMDのモーションで休んだり、ウィンドウの上を移動したり（四つんばいで進む、お尻をずらして進む、など）できます。組み込みのもの（提供していただいたもの）のほか、メニューの「モーション」→「ウィンドウの上のモーションを開く...」で自分のVMDを加えられます（複数可。キャラクターごとに覚えます）。乗るたびに、使えるものから1つを選んで繰り返し、移動するものがあれば20〜60秒ごとにそれで横へ移動します。設定の「しぐさを選ぶ...」で、組み込みのものとアプリの「座る」「ぶら下がる」を使うかどうかを選べます。作り方の決まり（床をウィンドウの上端として、正面向きのループで作る、など）は [docs/WindowMotions.md](docs/WindowMotions.md) にあります
- 上端に立つと頭が画面の上にはみ出すウィンドウ（最大化したウィンドウなど）のときは、その画面の右下の地面へ移ります
- 乗っているウィンドウが動けば一緒に動きます。最小化されたり閉じられたりすると落下します
- 座っているとき、ウィンドウに重なっている脚（下半身から足先まで、スカートの幅を含む）にカーソルが近づくと、横へ少しだけ（身長の3割ほど）歩いてよけ、その場でまた座ります。元の位置には戻りません。上端より上の部分や、脚から横に離れた位置では避けないので、つまむ・右クリックはそこでできます（ぶら下がっているときは体がウィンドウの後ろなので避けません）
- つまんで離したとき、真下に前面のウィンドウがあれば、その上端に着地します
- 全画面アプリ（ゲームやプレゼンテーション）の実行中は、自動で非表示になり描画も止まります

## 外部アプリからの操作（HTTP API）

ほかのアプリやスクリプトから、キャラクターにしゃべらせたり、しぐさ・モーション・歩きをさせたりできます。設定の「詳細」にある「外部から操作」をオンにすると（既定はオフ、ポートは50080。OKを押すとすぐに反映され、再起動はしません）、このコンピューターの中だけで受け付ける小さなHTTPサーバー（`http://127.0.0.1:50080`）が動きます。

- 受け付けるのはこのコンピューターからだけです（127.0.0.1でだけ待ち受けます）。ほかのパソコンからは届きません
- ブラウザで開いたWebページからの要求は断ります（`Origin` ヘッダーのある要求と、`Host` が `127.0.0.1`・`localhost`・`[::1]` 以外の要求）。そのため、見ているサイトが勝手にキャラクターを動かすことはできません
- 本文はJSON（UTF-8）、答えもJSONです。成功すると `{"ok":true}`、うまくいかないと `{"ok":false,"error":"..."}` と、400（頼み方の誤り）・404（ないコマンドやキャラクター）・409（いまはできない）などの状態コードを返します
- `"character"` で何人目に頼むかを選べます（1〜6、省略すると1人目）。本文がJSONでないとき（VMDをそのまま送るとき）は、`/motion?character=2` のようにURLに付けます

| メソッドとパス | 本文 | 内容 |
|---|---|---|
| `GET /state` | なし | バージョンと、会話を外部アプリに任せているか（`externalChat`）と、キャラクターごとの名前・モデル・していること（`idle`、`walk`、`sit` など）・ウィンドウの上か・話しているか・モーション再生中か・居眠り中か・位置 |
| `GET /gestures` | なし | `/gesture` で使えるしぐさの名前と、`/say` の `feeling` に使える気持ちの名前 |
| `POST /say` | `{"text":"こんにちは","feeling":"smile"}` | 書いたとおりに吹き出しでしゃべる（声の設定があれば声も、口パクも）。LLMは使いません。`feeling` は省略できます（`smile`、`surprise`、`troubled`、`angry`、`sad`、`shy`、`neutral`） |
| `POST /say`（音声つき） | `{"text":"Hello!","audio":"<base64>"}` または `{"text":"Hello!","audioFile":"C:\\voice\\hello.mp3"}` | 外部で作った音声と一緒にしゃべる。どの言語でも使えます（口パクは音声の大きさから作るので、言葉を問いません）。吹き出しの文字は音声の長さに合わせて出ていきます。`audio` は音声ファイルの中身をbase64にしたもの（本文全体で16MBまで）、`audioFile` はこのコンピューターの音声ファイルのパス（64MBまで）。MP3、AAC（M4A）、WAV、FLAC など、Windowsで再生できる形式に対応（10分まで、モノラルかステレオ）。音声つきのときは、設定の声（VOICEVOX・AivisSpeech）は使いません |
| `POST /talk` | `{"text":"今日は何の日？"}` | あなたが話しかけたのと同じ扱いで、LLMが返事をする（会話の記憶にも残ります）。タイマーなどの頼みもそのまま通ります |
| `POST /gesture` | `{"name":"wave"}` | しぐさを1回する。アプリ標準の待機ポーズで立っているときだけです（待機モーションを使っているときや、歩いている・座っているときは409） |
| `POST /motion` | `{"path":"C:\\motions\\dance.vmd"}` | VMDをすぐに1回再生する（座っていれば立ち上がってから。ウィンドウの上にいるときは、いつものように画面右下へワープしてから）。終わると「モーションを開く」で開いたモーションに戻ります。設定ファイルには保存しません。再生中に頼むと409です |
| `POST /motion` | VMDファイルの中身そのもの（`Content-Type: application/octet-stream`、16MBまで） | ファイルのパスの代わりに、VMDのデータを直接送って再生する（ファイルに書き出さずに作ったモーションなど）。動きは上と同じです。受け取ったデータは一時ファイルにして読み込み、すぐに消します |
| `POST /motion/stop` | なし | 再生中のモーションをなめらかに止める（まだ始まっていなければ取り消す） |
| `POST /walk` | `{"dx":-300}` または `{"x":800,"run":true}` | いまいる面の上を、`dx` ピクセル横へ（マイナスで左）、または画面の横位置 `x` まで歩く（`run` が `true` なら走る）。つままれている・ワープ中などは409 |

例（PowerShell）：

```powershell
Invoke-RestMethod http://127.0.0.1:50080/state
$body = [Text.Encoding]::UTF8.GetBytes('{"text":"ビルドが終わったよ！","feeling":"smile"}')
Invoke-RestMethod http://127.0.0.1:50080/say -Method Post -ContentType "application/json" -Body $body
```

例（Git Bash などの curl）：

```bash
curl -s -X POST http://127.0.0.1:50080/walk -H "Content-Type: application/json" -d '{"dx":-300}'
```

VMDをそのまま送る例（PowerShell）：

```powershell
Invoke-RestMethod "http://127.0.0.1:50080/motion?character=1" -Method Post -ContentType "application/octet-stream" -InFile "C:\motions\dance.vmd"
```

音声つきでしゃべらせる例（PowerShell）：

```powershell
$audio = [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\voice\hello.mp3"))
$body = [Text.Encoding]::UTF8.GetBytes((@{text="Hello! The build is done."; audio=$audio} | ConvertTo-Json))
Invoke-RestMethod http://127.0.0.1:50080/say -Method Post -ContentType "application/json" -Body $body
```

Python なら `requests.post("http://127.0.0.1:50080/gesture", json={"name": "wave"})` や、`requests.post("http://127.0.0.1:50080/motion", data=vmd_bytes, headers={"Content-Type": "application/octet-stream"})` のように呼べます。Claude Desktop などのMCPクライアントからは、このAPIを呼ぶstdioのMCPサーバーを用意すれば、トンネルなしで使えます。

### アプリからの知らせ（イベント）と、会話を任せる

`GET /events` につなぐと、つないでいる間、キャラクターに起きたことが届きます（Server-Sent Events。`event:` に種類、`data:` にJSON）。同時に8本までつなげます。

| イベント | いつ | data の例 |
|---|---|---|
| `hello` | つないだとき | `{"chat":"app"}`（会話を外部アプリに任せている間は `"external"`） |
| `said` | あなたが入力欄でキャラクターに話しかけたとき | `{"character":1,"text":"今日の天気は？","answeredBy":"external"}`（`answeredBy` は返事をする側。`app` はこのアプリ（LLM、タイマーなど）） |
| `spoke` | キャラクターがセリフを言い終えたとき（次のセリフで途中から切り替わったときは出ません） | `{"character":1,"text":"晴れだよ。"}` |
| `speakFirst` | 会話を任せている間に、キャラクターが自分から話しかけようとしたとき（あいさつ、ひと言など） | `{"character":1,"situation":"夕方から夜の時間です。…"}` |
| `click` | クリックされたとき | `{"character":1,"part":"head"}`（`head` か `body`） |
| `held` | つままれた・離されたとき | `{"character":1,"held":true}` |
| `doze` | 居眠りを始めた・起きたとき | `{"character":1,"dozing":true}` |
| `motionEnd` | モーションの再生が終わったとき | `{"character":1,"fromApi":true}`（`/motion` で頼んだものなら `true`） |

15秒ごとに、何も起きていなくても `: ping` の行が届きます（切れたことに気づくため）。

**会話を任せる**：`GET /events?chat=external` でつなぐと、つないでいる間は、あなたが入力欄で話しかけた言葉がLLMには行かず、`said` で外部アプリに届きます。外部アプリが `/say`（音声つきも可）で答えると、キャラクターがそれを言います。答えを待つ間は吹き出しに点々が出て、1分たっても答えがなければ消えます。自分から話しかける時（あいさつなど）も、LLMの代わりに `speakFirst` が届きます（タイマーや更新の知らせのように、必ず伝えることは、決まった文でそのまま言います）。タイマー・リマインダー・やることの頼みは、これまでどおりこのアプリが受けます。外部アプリの接続が切れると（遅くとも15秒ほどで）、元どおりLLMが返事をします。

Python で、話しかけられたらオウム返しする例：

```python
import json, requests
with requests.get("http://127.0.0.1:50080/events?chat=external", stream=True) as r:
    event = None
    for line in r.iter_lines(decode_unicode=True):
        if line.startswith("event: "):
            event = line[7:]
        elif line.startswith("data: ") and event == "said":
            said = json.loads(line[6:])
            if said["answeredBy"] == "external":
                requests.post("http://127.0.0.1:50080/say",
                              json={"character": said["character"], "text": "「" + said["text"] + "」って言ったね。"})
```

## 設定（exeと同じフォルダの `MikuMikuDesktopPerch.ini`、UTF-16）

1人目のキャラクターの設定は `[Mascot]` セクションに、ほかの設定と一緒に入ります。2〜6人目は `[Mascot2]`〜`[Mascot6]` に、キャラクターごとの項目（Model、Motion、IdleMotion、ClickMotion、WalkMotion／RunMotion、X、VoiceSpeaker／VoiceName）だけが入ります。

| キー | 既定値 | 内容 |
|---|---|---|
| Model | （初回起動時にファイル選択） | PMXファイル |
| Motion | 空 | 「モーションを開く」で開いたVMD（ときどき1回ずつ再生） |
| IdleMotion | 空（アプリ標準の待機ポーズ） | 待機中に再生するVMD。複数のときは `\|` 区切り |
| ClickMotion | 空（組み込みの反応） | クリックしたときに再生するVMD。複数のときは `\|` 区切り |
| WindowMotion | 空 | ウィンドウの上のモーション（自分で追加したVMD）。複数のときは `\|` 区切り |
| ToonDir | 空 | 共有トゥーン `toon01.bmp`〜`toon10.bmp` の置き場所（MMDの `Data` フォルダ）。空のときは近似グラデーションを使います |
| Height | 300 | 大きさ100%のときの、身長20（MMDの単位。標準的なモデルの身長）のモデルの高さの目安（96 DPI基準の論理ピクセル）。大きさはMMDの単位で決まり、モデルごとの身長の違いはMMDと同じに表れる（アクセサリで小さくならない） |
| Scale | 100 | 大きさ（%、50〜600。全員共通）。300%より大きいときは300%の解像度で描いて拡大表示する（GPUの負担は300%のときと同じ） |
| Language | 空（自動） | 言語。`ja`（日本語）、`en`（英語）、空のときはWindowsの表示言語に合わせる |
| X | -1 | マスコットの横位置（画面のピクセル）。-1のときは画面の右端（縦位置は常に地面に合わせます） |
| AutoBehavior | 1 | おまかせ行動（地面でひとりで歩く） |
| WindowMode | 0 | アクティブウィンドウモード |
| Fps | 30 | 描画fps |
| MotionBlur | 0 | 1でモーションブラー（動いているところを動きの向きにぼかし、低いfpsでもなめらかに見せる） |
| Physics | 1 | 物理演算のオン/オフ |
| PhysicsFps | 60 | 物理演算の内部ステップ数（回/秒）。描画の1コマごとに同じ回数ずつ進める（描画fpsの整数倍に切り上げ） |
| PhysicsFilter | 3 | 物理演算の震え止め（0なし、1弱、2中、3強）。髪やスカートの小刻みな震えだけをならす。じっとしているときは強め、動いているときは弱めに効く |
| PhysicsIterations | 10 | 物理演算の1ステップで拘束を解く反復回数（1〜100）。増やすと長い髪などの細かい震えが減るが、少し重くなる |
| Msaa | 4 | アンチエイリアスのサンプル数（1/2/4/8）。GPUが対応していない数は、対応している数まで下げます（どれも無理ならなし）。古いインテルのグラフィックドライバでは、ここにかかわらずなしで描きます（「困ったとき」を参照） |

## 安全のために

モデルやモーションは配布物をそのまま開くことが多いので、壊れたファイルや細工されたファイルで問題が起きにくいようにしています。

- **読み込む前の確認**：PMXは先頭が `PMX ` でバージョン2.0／2.1、1GB以下のものだけ、VMDは先頭が `Vocaloid Motion Data` で512MB以下のものだけを読み込みます。拡張子だけ変えたファイルや大きすぎるファイルは、パーサーに渡す前に断ります
- **壊れたデータ**：PMXLoaderが読み込み中や姿勢計算の準備中にメモリ違反を起こしても、異常終了せずにエラーとして扱います（PMX・VMDとも）。範囲外の参照を含むモデルは表示前に弾きます。設定の待機モーションが読み込めないときは、それを外してモデルだけ表示します
- **テクスチャ**：別のコンピューターを指すパス（`\\server\share\...` など）は開きません（Windowsがその相手に接続して資格情報を渡してしまうのを防ぐため）。ドライブ名の後にもコロンを含むパス（代替データストリームなど）も開きません。画像はWindows標準のBMP・PNG・JPEG・GIF・TIFFだけを、拡張子ではなく中身で判定して読み込みます（後から入れた画像コーデックは使いません）。大きさは縦横16384ピクセルまでです
- **DLL**：名前で読み込むDLLを、作業フォルダからは探さないようにしています
- **外部アプリからの操作**：既定はオフです。オンにしても127.0.0.1でだけ待ち受け、`Origin` ヘッダーのある要求や、`Host` がこのコンピューター以外の要求（Webページからのもの、DNSリバインディング）は断ります。本文は64KBまで（`/say` と、VMDをそのまま送るときだけ16MBまで）です。送られた音声は、Windowsに入っているMedia Foundationで読み込みます
- **ビルド**：Control Flow Guard、CET互換、ASLR、DEPを有効にしています

## 対応するモデル

- **人型の判定**：センター、上半身、下半身、首、頭、左右の腕・ひじ・足・ひざ・足ＩＫがそろっていて、かつ骨格が人型の形をしていること（頭 > 首 > 上半身 > ひざの順に高く、上半身から頭がほぼ垂直で、腕が体の横に伸びている）。条件を満たさないモデルは、理由を表示して読み込みません
- **Tスタンス**：腕の角度が水平から20°未満のモデルは、MMD標準に近いAスタンス（35°）まで腕を下ろして表示します。子ボーンのキー回転は補正に合わせて変換するので、ひじや手首も元のモーションどおりに曲がります
- **大きさの測り方**：画面に出す大きさと位置は、表示される材質（最初から透明なものを除く）の頂点のうち、骨格の近くにあるものだけで測ります。遠くに置かれた非表示の小物や余分な頂点があっても、キャラクターが小さくなりすぎません
- **アルファが全部0のテクスチャ**：32ビットのTGA・BMPで、アルファがすべて0のものは不透明として扱います（MMDと同じ見え方になり、材質ごと消えません）。PNGのアルファはそのまま使います
- **壊れたデータ**：付与フラグがあるのに付与親がないボーンは、その付与だけを無効にして読み込みます。範囲外の参照を含むモデルや、PMXLoaderが読み込み中に異常終了するモデルは、メッセージを出して弾きます

## 困ったとき（ログ）

起動するたびに `%LOCALAPPDATA%\MikuMikuDesktopPerch\log.txt`（UTF-8）へ、アプリのバージョン、Windowsのバージョン、モニターの配置、使っているGPUとドライバ、読み込んだモデルの頂点数と大きさ、テクスチャごとの読み込み結果、キャラクターを置いた位置、表示したエラーなどを書きます。前回の分は `log.old.txt` に移すので、ファイルは2つより増えず、1つは512KBで書くのをやめます。モデルが表示されないなどの問題を知らせていただくときは、このファイルを添えてください（モデルのファイルのパスが含まれます）。

GPUが応答しなくなって（ドライバのリセットなど）描画できなくなったときは、その旨を表示して再起動するか尋ねます。

**アンチエイリアスを入れるとモデルが消える**：古いインテルのGPUのドライバでは、アンチエイリアス（MSAA）でモデルが描かれないことがあります。そのため、インテルのGPUでドライバが2020年より前のもの（バージョンの最初の数字が27より小さいもの。例：20.19.15.x、26.20.100.x）のときは、設定にかかわらずアンチエイリアスなしで描き、キャラクターが一度だけ、ドライバを更新するよう知らせます。インテルのサイト（またはパソコンのメーカーのサイト）からドライバを更新すると、アンチエイリアスが使えるようになります。ほかのGPUでも、選んだサンプル数に対応していなかったり、描画の準備に失敗したりしたときは、アンチエイリアスなしで描きます。どの場合も、`log.txt` に `MSAA` で始まる行（または `drawing: MSAA x1`）が残ります。それでも消えるときは、設定の「詳細」でアンチエイリアスを「なし」にして、`log.txt` を添えて知らせてください。

## 診断用オプション

```
MikuMikuDesktopPerch.exe --snapshot out.png [frames]
```

指定したフレーム数（既定は60）を描画したあと、最後のフレームを `out.png`（premultiplied BGRA）に保存して終了します。
`--look <x> <y>` を付けると、視線追従用のカーソル位置をクライアント座標で固定できます。
`--model <pmx>` で別のモデルを、`--scale <percent>` で大きさを指定できます。`--rest-pose sit|hang` でウィンドウ上の休憩ポーズを固定でき、`--walk <px>` で起動3秒後にその距離だけ歩かせられ（右が正）、`--shove <px>` で起動2秒後にその距離だけ横へ動かせ（画面の外へも動かせるので、走って戻ってくるのを試せます）、`--say <文>` で起動1秒後にその文を吹き出しで話させられ、`--click head|body` で起動1.5秒後に頭／体をクリックしたときの反応をさせられ、`--play-motion` で設定のモーションを起動直後に再生でき、`--gesture hip|wave|peace|behind|palm|folded|stretch|look|tilt|stand|hair|yawn|think|hum|clap|far|cheeks|dangle|swing|shake|wrist|fingers|shoulders|shrug|sigh|back|down|up|glance|neck|nod|drowse|sway|twist|peek|bounce|tap|pat|surprised|curious|shynod` で待機中のしぐさ（後ろの4つはクリックの反応）を固定でき（`stretch@3.5` のように秒数を付けると、動きのあるしぐさをその時点で止めて撮れます）、環境変数 `MIKUMIKUDESKTOPPERCH_LOG` にファイル名を設定すると行動の判断過程を書き出します。`--clearance` を `--gesture` と一緒に付けると、しぐさを0.1秒ずつ進めながら、前腕と手が体（髪と腕を除く頂点）にいちばん近づく距離と、その頂点のボーンを `out.png.txt` に書き出します（物理演算は切り、環境変数 `MIKUMIKUDESKTOPPERCH_SEED` に数を入れると重心移動などの乱数が毎回同じになるので、立ちポーズと比べられます）。`--only-gestures hip,dangle,clip:名前` を付けると、待機中のしぐさをそれだけに絞って試せます（`--idle-clip` のものの名前はファイル名です）。`--idle-clip <vmd>` を付けると、そのVMDを組み込みの待機モーションに加えて試せます（`--gesture clip0@5` のように番号と秒数で、その時点の姿勢を撮れます。番号は埋め込みのものの後に続きます。`--clearance` とも使えます）。`--window-clip <vmd>` を付けると、そのVMDをウィンドウの上のモーションに加え、`--activity sit|hang|walk` と `--window-motion <番号>`（`--direction -1|1` で向き）で、その姿で撮れます。`.txt` に、ウィンドウの上のモーションをそれぞれどう扱ったか（前か後ろか、休むか移動するか）を書きます。`--perch-window <ウィンドウのタイトル>` で1人目をそのウィンドウに乗せ（`test` にすると、試し用のウィンドウを自分で出します）、乗る・休む・移動するのを実際の動きで試せます。`--activity walk|run|jump|sit|lie|hang|grab|fall` を付けると、その生成モーションを固定したまま撮影し、`--view-yaw <度>` でカメラを回り込ませて横から撮れます。診断用の起動では設定ファイル（ini）を書き換えず、同じ場所に `out.png.txt`（腕の角度、補正量、ウィンドウサイズ、エラー内容）を書き出します。
`--calendar-test <in.ics> <out.txt>` で、iCalファイルにある今日から3日分の予定を、Googleカレンダーから読み込んだときと同じように書き出します。
`--plan-test <in.txt> <out.txt>` で、in.txt（UTF-8）の1行ずつを、タイマー・リマインダー・やることの頼みとしてどう読み取るかを書き出します（行の先頭に `~` を付けると、一覧の画面で追加するときの読み方になります）。
`--banter` で起動の5秒後にキャラクター同士のおしゃべりを始め、`--pretend-version <バージョン>` でこのexeをそのバージョンとみなして更新の確認から更新までを試せ（すぐに確認します）、`--reading <文> <out.txt>` で口パクに使う読みを書き出せます。
`--voice-test <VOICEVOXのフォルダ|http://エンジンの接続先> <声のID> <out.wav> [スタイルの強さ]` で VOICEVOX のファイルを直接使って（または音声エンジンで）1文話させ（結果と、音節ごとの時刻は `out.wav.txt`）、`--light <左右> <高さ>` で太陽の位置を、`--self-shadow 0|1` でセルフシャドウを切り替え、`--doze` でうとうとした姿を撮れ、`--walk-motion <vmd>`・`--run-motion <vmd>` で歩く・走るモーションを指定できます。
`--gpu-quirk old-driver` で古いインテルのドライバのとき（アンチエイリアスなし、知らせが1回）を、`--gpu-quirk whole-resolve` で描いた範囲だけのMSAAの解決（ResolveSubresourceRegion）ができないGPUのときを試せます。`out.png.txt` の `gpu=` の行に、実際に使ったサンプル数が出ます。

```
MikuMikuDesktopPerch.exe --check-list <list.txt> <out.tsv>
```

`list.txt`（UTF-8、1行に1つのPMXパス）に並べたモデルを、ウィンドウを開かずに順に読み込みます。人型の判定とTスタンスの判定の結果を、`out.tsv` に書き出します。

### 待機モーションを組み込むには

1. VMDを `res\idle\` に置きます（標準のボーン名だけを使い、最初と最後は自然な立ち姿に近く、足の位置は動かさないか最後に戻したものが向いています）
2. `res\MikuMikuDesktopPerch.rc` の末尾に `名前 IDLECLIP "idle\\ファイル名.vmd"` の1行を加えます。名前は半角英数字で（リソースの名前になり、大文字にそろえられます。設定に `clip:名前` として残るので、あとから変えないでください）
3. `res\idle\names.txt`（UTF-8）に `名前<タブ>日本語の表示名<タブ>英語の表示名<タブ>作者（日本語）<タブ>作者（英語）` の1行を加えます（設定の「しぐさを選ぶ...」に「モーション：あくび（絢姫 様）」のように出ます。作者は省略できます）。ビルドします
4. 何体かのモデルで `--idle-clip` と `--clearance` を使い、手が体にめり込まないか確かめます
